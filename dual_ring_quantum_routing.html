Dual-ring quantum key routing for nine grid supernodes

Each supernode makes encryption keys with its neighbours by QKD (keys sent as single photons). Two rings run opposite ways, so when a spy taps one span, the key goes the other way round to the command center.

The real ring's layout is not public, so this is the team lead's design with illustrative distances: 8.5 km spans and 6 km gateway links. Open this ring in the live 3D grid

How the router picks a path

It runs Dijkstra's shortest-path search from the sender to the command center, over every span that can still make key. On this page each span costs:

cost = length × (1 + 10 × QBER)

QBER is the share of key bits that arrive wrong. A clean ring span reads 1.8% and a gateway link 1.5%. A tapped span reads 26.8%, above the 11% limit, so it is dropped from the search.

Simplified rule here: alarm at 8%, no key above 11%. The live 3D grid uses each fiber's own measured baseline (about 3.3% on a 10 km fiber) and a statistical alarm.

Each span is one QKD fiber pair carrying both rings in one corridor, so a tap cuts both directions on that span. With no quantum path left, traffic falls back to an ML-KEM-768 tunnel (post-quantum backup encryption).
